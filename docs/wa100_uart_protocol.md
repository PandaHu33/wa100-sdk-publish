# WA100 RS485 通信协议

> 本文档说明 **RS485 通信层**：帧格式、校验、命令与回包。
>
> 使用“**关节**”概念描述设备的 6 路通道（`id = 1..6`）。

---

## 1. 串口参数（RS485）

推荐串口参数（以设备实际配置为准）：

- 串口：COM1
- 波特率：`1000000`
- 数据位：8
- 校验：None
- 停止位：1
- 流控制：0
- 超时设置：100ms
建议通信策略：一次发送一帧，收到应答后再发送下一帧。

---

## 2. 字节序

- 所有 `uint16` 均为 **小端序（Little Endian）**：低字节在前，高字节在后。

---

## 3. 帧格式（方向性帧头）

### 3.1 上位机 -> 设备（请求帧）

| 字段 | 偏移 | 长度 | 说明 |
|---|---:|---:|---|
| Header | 0 | 2 | 固定 `0x48 0x4D` |
| Length | 2 | 1 | **Data 字段长度 N**（不含 Cmd） |
| Cmd | 3 | 1 | 命令字 |
| Data | 4 | N | 命令负载 |
| Checksum | 4+N | 1 | 校验和 |

整帧长度（字节数）= `N + 5`。

### 3.2 设备 -> 上位机（应答帧）

应答帧结构相同，但帧头固定为 `0x48 0x4D`。

---

## 4. 校验算法（Checksum）

校验为 **8-bit 累加和**：

- 参与累加的字节范围：从 `Length` 字节开始，覆盖 `Cmd` 与 `Data`
- 不包含帧头
- 不包含 `Checksum` 自身

伪代码：

```text
sum = 0
sum += Length
sum += Cmd
for b in Data[0..N-1]:
  sum += b
Checksum = sum & 0xFF
```

---

## 5. 设备模型与 ID

- 固定 6 个关节：`id = 1..6`
- `id = 0`：用于 `Enable/EmergencyStop/ClearError` 的“全部关节”广播

---

## 6. 命令字定义

RS485 命令字：

| Cmd | 名称 | 含义 |
|---:|---|---|
| 0x01 | SET_POSITIONS | 定位模式：设置 6 路目标位置 |
| 0x02 | QUERY_CONFIGURE | 查询配置（按 id） |
| 0x03 | EMERGENCY_STOP | 急停（id=0 表示全部） |
| 0x04 | ENABLE | 使能（id=0 表示全部） |
| 0x05 | FOLLOW_POSITIONS | 随动模式：设置 6 路目标位置 |
| 0x06 | SET_ID | 修改关节 ID |
| 0x07 | OVERCURRENT_PROTECTION | 设置过流阈值 |
| 0x08 | OVERTEMP_PROTECTION | 设置过温阈值 |
| 0x09 | RISETEMP_START | 设置回温启动温度 |
| 0x0A | ERROR_CLEAR | 清除故障（id=0 表示全部） |
| 0x0B | SET_BAUDRATE | 修改波特率 |

---

## 7. 各命令数据格式

下文用 `N = Length` 表示 Data 字段长度。

### 7.1 0x01 / 0x05：设置 6 路目标位置

**请求（上位机 -> 设备）**

- `Length = 12`
- `Data = pos[6]`，每个 `pos[i]` 为 `uint16_le`

| 偏移 | 字段 | 类型 | 说明 |
|---:|---|---|---|
| 0 | pos1 | uint16_le | 目标位置 |
| 2 | pos2 | uint16_le | 目标位置 |
| 4 | pos3 | uint16_le | 目标位置 |
| 6 | pos4 | uint16_le | 目标位置 |
| 8 | pos5 | uint16_le | 目标位置 |
| 10 | pos6 | uint16_le | 目标位置 |

**应答（设备 -> 上位机）：状态回包**

- `Length = 37`
- `Data = status[6] + leakwarning`

每路 `status[i]` 6 字节：

| 相对偏移 | 字段 | 类型 | 说明 |
|---:|---|---|---|
| +0 | position | uint16_le | 当前位置 |
| +2 | current | uint16_le | 电流（单位以设备定义为准） |
| +4 | temperature | uint8 | 温度 |
| +5 | error_flags | uint8 | 故障位图 |

最后追加：

| 偏移 | 字段 | 类型 | 说明 |
|---:|---|---|---|
| 36 | leakwarning | uint8 | 漏水报警（0=正常；非0为漏水，其他值见数据定义） |

> 在 `FOLLOW_POSITIONS(0x05)` 的状态回包中，`error_flags` 会额外按位或 `0x40`（随动模式标志）。

### 7.2 0x03 / 0x04 / 0x0A：急停 / 使能 / 清故障

**请求**

- `Length = 1`
- `Data[0] = id`（1..6；0 表示全部；需要注意的是清故障0x0A不存在0即不存在一次清全面设备故障指令，若有需要则得依次单独清除6个设备的故障）

**应答**

- 状态回包（同 7.1 的应答格式，`Length = 37`）

### 7.3 0x02：查询配置

**请求**

- `Length = 1`
- `Data[0] = id`（1..6）

**应答（设备 -> 上位机）：配置回包**

- `Length = 9`

| 偏移 | 字段 | 类型 | 说明 |
|---:|---|---|---|
| 0 | id | uint8 | 关节 ID |
| 1 | baudrate_code | uint8 | 0=19200, 1=57600, 2=115200, 3=921600 |
| 2 | current_protection | uint16_le | 过流阈值（mA） |
| 4 | overtemp_x10 | uint16_le | 过温阈值（单位 10℃） |
| 6 | risetemp_x10 | uint16_le | 回温启动温度（单位 10℃） |
| 8 | leakwarning | uint8 | 漏水报警 |
- 注：过温阈值以及回温启动温度存在10倍偏移，即如果收到数据是800，则代表80℃。

### 7.4 0x06 / 0x0B：修改 ID / 修改波特率

**请求**

- `SET_ID(0x06)`：`Length = 2`，`Data = [current_id, new_id]`
- `SET_BAUDRATE(0x0B)`：`Length = 2`，`Data = [id, baudrate_code]`

**应答：ACK 回包**

- `Length = 1`
- `Cmd = 原命令字`
- `Data[0] = 0x01` 成功，`0x00` 失败

### 7.5 0x07 / 0x08 / 0x09：设置保护阈值/回温启动

**请求**

- `Length = 3`
- `Data = [id, value_lo, value_hi]`（其中 `value` 为 `uint16_le`）

三条命令分别表示：

- `0x07 OVERCURRENT_PROTECTION`：`value = threshold_mA`（mA）
- `0x08 OVERTEMP_PROTECTION`：`value = threshold_x10`（0.1℃）
- `0x09 RISETEMP_START`：`value = threshold_x10`（0.1℃）
- 注：过温阈值以及回温启动温度存在10偏移，即如果需要设置80℃，则需要下发数据是800。

**应答**

- ACK 回包（同 7.4）

## 8. 故障码（error_flags）位定义

`error_flags` 为位图（按位或组合）：

| Bit | 掩码 | 名称 | 说明 |
|---:|---:|---|---|
| Bit | 掩码 | 含义 |
|---:|---:|---|
| 0 | 0x01 | 堵转保护 |
| 1 | 0x02 | 过温保护 |
| 2 | 0x04 | 过流保护 |
| 3 | 0x08 | 驱动/电机异常 |
| 4 | 0x10 | 通信错误 |
| 5 | 0x20 | 响应超时 |
| 6 | 0x40 | 随动模式标志 |
| 7 | 0x80 | 设备离线 |

---

## 9. 时序与实现注意事项

- 建议采用“请求-应答”方式：发送 1 帧请求后等待应答，再发送下一帧。
- 接收端需要能处理粘包/分包：在字节流中查找帧头（`48 4D`），按 `Length + 5` 重组完整帧。

---

## 10. 报文示例（Hex，含校验）

### 10.1 查询配置（0x02）查询 id=1

请求（`48 4D` 方向帧头）：

```text
48 4D 01 02 01 04
```

校验：`01 + 02 + 01 = 04`。

### 10.2 设置位置（0x01）6 路都为 2000 (0x07D0)

请求：

```text
48 4D 0C 01 D0 07 D0 07 D0 07 D0 07 D0 07 D0 07 17
```

校验计算：

- `Length + Cmd = 0C + 01 = 0D`
- Data：`(D0+07) * 6 = D7 * 6 = 0x0A (mod 256)`
- 总和：`0D + 0A = 17`

### 10.3 ACK 示例：设置过流（0x07）成功

应答（`48 4D` 方向帧头）：

```text
48 4D 01 07 01 09
```

校验：`01 + 07 + 01 = 09`。
